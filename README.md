# Unicode Typer

DOCX의 본문과 서식을 읽고 Google Docs에 한 글자씩 타이핑하는 Windows 앱입니다. 일반 글 모드에서는 다른 Windows 앱에도 문자를 입력할 수 있습니다. 본문을 Ctrl+V, HTML 주입, 문서 가져오기 또는 Docs API로 넣지 않습니다.

## 다운로드

**[Google Docs / DOCX 미리보기 0.5 다운로드](https://github.com/KEYSTONE360/unicode-typer/releases/tag/docs-v0.5.0-preview)**

`UnicodeTyper-Docs-Preview.exe`를 내려받거나 ZIP을 풀어 실행합니다. Windows 10/11 x64용이며 Python 설치는 필요하지 않습니다. Chrome 또는 Edge가 필요합니다. EXE에는 코드 서명이 없습니다.

현재 소스는 개발용 미리보기입니다. 이전 일반 글 전용 실행 파일은 [v1.0.0](https://github.com/KEYSTONE360/unicode-typer/releases/tag/v1.0.0)에 남아 있습니다.

## 사용 방법

1. 앱의 **Google Docs 브라우저 열기**를 누릅니다. 별도 브라우저 프로필에서 필요한 경우 직접 로그인합니다.
2. 편집 가능한 빈 Google 문서 탭을 하나만 열어둡니다.
3. **DOCX 불러오기**로 문서를 선택하고 **분석 / 실행 명령**을 확인합니다. 원본 DOCX는 수정하지 않습니다.
4. 시작 대기와 글자 간격을 설정하고 **타이핑 시작**을 누릅니다.
5. 대기시간 안에 전용 브라우저의 문서 입력 위치를 클릭합니다.
6. 다른 창에서도 **F8**로 중단할 수 있습니다. 일반 글을 입력하려면 **일반 글 모드**를 선택합니다.

| 설정 | 범위 | 기본값 |
|---|---|---|
| 시작 전 대기 | 1~60초 | 5초 |
| 글자 사이 대기 | 0.01~5,000ms, 소수점 지원 | 50ms |

`0.5`, `12.5`, `50.25`처럼 입력할 수 있습니다. 1,000ms는 1초입니다. 실제 입력 간격은 Windows 및 대상 앱 처리시간에 따라 달라집니다. 중단 후 시작하면 처음부터 다시 입력하며 이미 입력한 글은 삭제하지 않습니다.

## 0.5의 표 입력 수정

0.4에서는 표 선택기를 열어도 키보드 포커스가 상단 메뉴에 남아, 오른쪽 방향키가 표 크기 대신 서식 메뉴로 이동하는 실패를 실제 Google Docs에서 재현했습니다.

0.5는 실제 격자 크기를 측정해 한 행짜리 표를 클릭으로 만들고, 마지막 셀에서 Tab으로 행을 늘린 다음 Shift+Tab으로 첫 셀에 돌아옵니다. 셀 내용은 논리 좌표에 맞춰 이동하면서 문자별 키 이벤트로 전송합니다. 실제 접근성 메뉴와 글꼴 선택기 식별자도 반영했습니다.

글자 색, 셀 배경색, 기본 머리말/바닥글, 페이지 번호, 직사각형 병합, 열 너비, 문단 간격의 실행 경로를 포함합니다. 기능별 실패는 다른 서식 및 본문 입력과 분리하며 동일한 실패를 계속 재시도하지 않습니다.

## 경고와 호환 범위

- 미지원 요소나 서식 실패는 **경고 내역**에 기록하고 계속 진행합니다. 적용하지 못한 요소가 원본과 다르게 보일 수 있습니다.
- 표 생성 자체가 실패하면 내용을 일반 글로 이어서 입력합니다. 병합만 실패한 경우에는 표를 유지하고 빈 셀을 건너뛰어 좌표에 맞춰 입력합니다.
- F8, 대상 창/탭 변경, 연결 끊김, 키 전송 실패 또는 문서 입력 포커스 복구 불가는 중단합니다.
- Docs의 일부 표 이동에는 스크린리더 지원이 필요하며, 앱은 상태를 확인한 뒤 필요할 때 Ctrl+Alt+Z로 켭니다.
- Google Docs UI 변경, 사용할 수 없는 글꼴, 캔버스 편집기의 셀 경계 비노출, 복잡한 병합/구역/페이지 배치는 제한 사항입니다. **모든 DOCX의 서식이 완전히 유지된다고 보장하지 않습니다.**
- 전용 브라우저의 로그인 세션은 해당 브라우저 프로필에 남을 수 있습니다. 앱이 계정 비밀번호를 읽거나 배포 파일에 넣지 않습니다.
- 관리자 권한 앱 또는 합성 키 입력을 차단하는 보안 입력창/게임은 일반 글 모드에서도 지원이 제한될 수 있습니다.

자세한 명령 및 미지원 요소는 [DOCS_COMMANDS.md](DOCS_COMMANDS.md)를 참조하십시오.

## 검증 상태

실제 Google Docs UI에서 다음을 확인하고 내보낸 DOCX의 구조 및 내용을 대조했습니다.

- 2행 3열 표 생성과 여섯 셀의 한글/영문 입력
- 8행 3열 표 생성과 첫 셀/마지막 셀 이동 및 입력
- 표 밖으로 이동한 뒤 본문 입력

이는 **Windows EXE 전체 흐름을 끝까지 실행한 검증과는 다릅니다.** EXE 전체 자동 흐름 및 복잡한 병합/너비/색/페이지 배치의 원본 일치 검증은 남아 있습니다. 확인 범위는 [검증 기록](validation/google-docs-ui-0.5.json)에 명시했습니다. 개인 원본 문서, 계정 정보, 로그인 세션은 저장소와 Release에 포함하지 않습니다.

## 소스 실행과 빌드

소스 실행/빌드는 Windows의 Python 3.14 x64를 기준으로 합니다.

```powershell
python -m pip install -r requirements-build.txt
python typer.py
```

빌드:

```powershell
./build.ps1
```

빌드 결과는 `dist/UnicodeTyper.exe`입니다. 로컬 테스트는 Node.js도 필요합니다.

```powershell
python -m unittest test_commands test_rich_features test_warning_continue test_style_recovery test_browser_reconnect test_tables test_timing -v
```

EXE를 내려받아 사용하는 경우 Python/Node.js 설치는 필요하지 않습니다. `SHA256SUMS.txt`로 Release 파일 무결성을 확인할 수 있습니다. 저장소 공개 자체가 별도 소스 재라이선스 권한을 부여하지는 않습니다.
